# F02: сообщения между заявками и общая квалификация

15 ноября 2026, миграция22. Проверка:357 PASS/0 FAIL/0 SKIP на изолированном PG16.16; typecheck PASS. Лог `outputs/res01-lifecycle-2026-11-15/tests.log`. Production и реальные аккаунты не менялись. Сборка/compiled transport smokes повторяются вместе с F03.

Закрытая личка продолжает проверяться в пределах разрешённого scope. Курсор после смены фазы не перескакивает через непрочитанный промежуток. До отправки AI coordinator синхронизирует все известные каналы контакта; недоступный канал/пробел/scope останавливает отправку. Поступивший отказ отменяет pending-действия во всех каналах. Сообщения вне активного периода не становятся входом новой квалификации и сохраняются без текста; проверка явного отказа выполняется по входному событию в той же транзакции. Late service echo сохраняет прежнюю receipt-фазу и защиту TTL. Poll batches выбираются по давности курсора, чтобы первые100 контактов не вытесняли остальные.

Одна открытая заявка читает принятые поля обоих каналов с подтверждением цитаты в её фазах. В общем контексте messageId — глобальный event key, поэтому одинаковые внешние IDs разных мессенджеров не подменяют доказательство. Новейшая подтверждённая цитата определяет значение поля. Лимит ответов считается суммарно; дополнительный канал наследует закреплённые критерии заявки. Несовместимые версии критериев требуют передачи менеджеру. Предыдущая закрытая заявка в память не входит. Числа с запятой допускаются без пересчёта единиц, изменения знака или частичного совпадения числа.

Реальная сверка протоколов, качества модели и многосессионной нагрузки остаётся F08. Гарантия относится к истории, возвращённой проверенным transport: отсутствующую/неполную историю система не считает доказанным отсутствием отказа.
