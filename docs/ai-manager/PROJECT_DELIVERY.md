# Состояние поставки Relayboard

Обновлено15 ноября2026. Разработка по [плану завершения](RELEASE_COMPLETION_PLAN.md); история доказательств — [progress.md](progress.md). Это не акт производственной приёмки.

Автономные F01–F05 завершены: история отдельных заявок и ссылки менеджеру; защита устаревшей карточки/конкурентных настроек; общая подтверждённая квалификация одной заявки между MAX/WhatsApp; отказ после закрытия; подготовленные отправки и receipts; четыре причины handoff и четыре сценария дожима; настраиваемые тексты/параметры/этапы; экономное хранение и зашифрованное восстановление. Полный исходный объём RES00–10 и TC01–12 сохраняется.

Текущая схема —23 миграции. Проверено364 теста без ошибок/пропусков, typecheck/build, owner/SIGKILL/Chrome smokes; полный synthetic recovery поднял PG/Redis/API с прежними unknown/hold/opt-out/cursor/dedup и0 resend. Лицензии/зависимости подготовлены воспроизводимо, npm audit0 известных уязвимостей. Это не оценка качества настоящего GigaChat и не подтверждение реального WhatsApp login.

F06:24ч нагрузочный прогон выполняется, до полного завершения не PASS. F07: Linux RC строится из чистого git archive и проверяется в отдельной сети без реальных подключений. Конкретные source commit/image digest и финальные результаты сохраняются в release manifest после проверки. Требование ресурсов5+5 реальных сессий пока не подтверждено.

Реальные MAX/WhatsApp сценарии, коммерческий GigaChat, утверждённые бизнес-правила, полномочия обработки рабочих данных, актуальный production backup и конкретное разрешение установки — единый финальный этап F08. Рабочий VPS в этом продолжении не обновлялся. Настоящий локальный backend также не мигрировал; общий dist-web пересобран, поэтому локальные старые backend/assets не считать новым проверенным контуром.

Сборка: Node24, npm ci выполняет подготовку runtime-зависимостей; npm run build проверяет её. После npm ci --ignore-scripts нужно явно запустить scripts/prepare-runtime-dependencies.mjs. Проверка: npm run test:isolated с TEST_DATABASE_BASE_URL отдельного локального PG и9 созданными тестовыми БД. Реальные .env/ключи runner не загружает.

Копии: [recovery-runbook.md](recovery-runbook.md). Runtime/флаги и источники: runtime.md/source-monitor.md. Выпускать production до прохождения финальных условий нельзя.
