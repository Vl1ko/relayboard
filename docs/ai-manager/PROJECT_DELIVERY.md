# Состояние поставки, 13 ноября 2026

Это локальный пакет разработки, не подтверждение завершения всего ТЗ или выпуска.

Реализованы модули: CSV/XLSX; явные заявки; очередь первого обращения с паузой/стопом/продолжением, поздним чтением шаблона, durable interval и unknown guards; версии знаний/критериев и проверяемые решения; ручное управление, handoff и правила четырёх follow-up сценариев; grouped workspace; приём/проверка источников; синтетический worker. SQL v1–v9 применяется отдельно, не при запуске API. Worker и платформенные отправки по умолчанию выключены.

Актуальный выбор пользователя — GigaChat (13 ноября 2026); см. GIGACHAT.md. Предыдущая интеграция Яндекса сохранена. `yandex-provider.ts` использует фиксированный официальный endpoint и серверные ключи, bounded response и JSON parsing. Документация API: https://aistudio.yandex.ru/en/docs/ai-studio/text-generation/api-ref/TextGeneration/completion . Worker поддерживает fixture или Яндекс: AI_PROVIDER_MODE=yandex требует AI_ALLOW_EXTERNAL_REQUESTS=true и серверные YANDEX_API_KEY/YANDEX_FOLDER_ID. По умолчанию fixture и внешний доступ выключен. Живой API-запрос с ключом ещё не проверен. Настройки знаний, обязательных полей и критериев доступны в формах интерфейса; реальные правила задаёт владелец бизнеса. Новые версии не переписывают snapshot существующих диалогов.

## Локальная проверка

1. Создать отдельные тестовые PostgreSQL БД для каждого *_TEST_DATABASE_URL; имена проверяются тестами. Использовать только синтетические данные.
2. Подготовить synthetic .env с DATABASE_URL, Redis URL и фиктивными обязательными секретами. Не копировать production-сессии/ключи.
3. `npm run typecheck`, полный `npm test` с заполненными test URLs, `NODE_ENV=production npm run build`.
4. На отдельном стенде: базовая схема, затем `node --import tsx src/api/migrate-ai-manager.ts`; проверить ai_schema_migrations до v9.
5. API: CONTACT_IMPORT_ENABLED=true. Для имитации AI_SEND_MODE=synthetic и отдельно `node dist-node/ai-worker/index.js`. Закрытие браузера не останавливает worker. Compose overlay docker-compose.ai.yml включается только профилем synthetic-ai. Подтверждения синтетики не являются отправками MAX/WhatsApp.

## Подготовка выпуска и откат

До production: резервная копия БД/сессий, проверка восстановления в отдельной БД, diff к фактической серверной версии, PG16 regression (локальный прогон уже выполнен), build/version checksum, перечень зависимостей и лицензий, затем отдельное разрешение на конкретный выпуск. Additive миграции не откатываются удалением таблиц: это разрушает историю и dedup. Откат приложения — выключить новый worker/feature flag, вернуть предыдущую сборку, сохранить новые таблицы.

Остаток: реальное получение событий MAX/WhatsApp и доказательство provenance/native takeover; подготовленный live sender; реальный API Яндекса с согласованной моделью/ключом; подключение существующего поиска (не найден); браузерная приёмка интегрированного рабочего места; проверка на фактическом целевом сервере; аудит/совместимые обновления оставшихся зависимостей; runtime ресурсный профиль и backup/restore на целевом сервере. Нет письменного поручения и тестового списка реальных аккаунтов — реальные данные и сообщения не использовались.

Проверки этапов и ограничения описаны также в ai-engine.md, workflows.md, workspace.md, leads.md, first-outreach.md и progress.md. Ни тесты, ни этот документ не заменяют 12/12 live-приёмку.
