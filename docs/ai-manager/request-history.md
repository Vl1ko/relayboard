# История заявок и контекст команд менеджера

Проверено 15 ноября 2026 на изолированном PG16.16 и синтетическом UI. Полный набор: 349 PASS / 0 FAIL / 0 SKIP; typecheck и production build PASS. Доказательства: `outputs/res08-requests-2026-11-15`.

Карточка разделяет заявки контакта: источники, параметры/цитаты по каналам, решения, история сообщений, операции, этапы, уведомления и дожимы. Архив доступен для чтения; действия заявки доступны только при выборе текущей заявки канала. Приоритет и opt-out относятся ко всему контакту. Уведомление получает человекочитаемые причины и названия полей; необязательный PUBLIC_APP_URL создаёт ссылку на конкретную заявку, без секретов и произвольных адресатов из ответа модели.

Публичные команды менеджера передают expectedRequestId/expectedEpoch. После замены заявки либо смены поколения автоматики старая карточка получает конфликт; это касается ручного ответа, режима, статуса, этапов, дожимов и handoff. Принятый ручной ответ можно повторно запросить с тем же operationId и исходным payload: возвращается прежняя операция, новая отправка не создаётся. Внутренние действия workers сохраняют собственные проверки поколений.

Браузер: deep link, архив с5 тоннами отдельно от новой заявки, переключение MAX/WhatsApp, синтетическая ручная операция с сохранением квитанции после refresh; viewport390/document390. Настоящие аккаунты, модель, адресаты и production не использовались. Это не закрывает реальные TC02/04/05/10 и межканальную память квалификации (F02).
