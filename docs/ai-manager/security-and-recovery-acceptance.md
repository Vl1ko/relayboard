## API и файлы

- Произвольное отражение Origin с cookies заменено проверкой точного origin приложения. Посторонний сайт, соседний поддомен и неверная схема отклоняются до выполнения API. CLI без Origin поддерживается; dev-порт5173 разрешён только в development. Reverse proxy HTTPS использует PUBLIC_APP_URL.
- Cookies HttpOnly/SameSite Strict; включение Secure остаётся обязательной настройкой рабочего HTTPS-контура. Неверно закодированная cookie не вызывает внутреннюю ошибку. Login attempts очищаются по TTL и ограничены по числу записей; API key сравнивается через timingSafeEqual.
- Непредвиденный ответ API содержит incidentId вместо stack/SQL/внешнего текста. Лог такой ошибки не печатает payload. Проверка кода не обнаружила отключения TLS-проверки или прямых console-записей token/password/secret.
- Multipart сохраняется одной транзакцией. Сбой соединения/INSERT убирает только новые файлы; потерянный ответ COMMIT не удаляет потенциально зафиксированные вложения. Пустые файлы получают понятную ошибку. Непривязанные метаданные/файлы черновика истекают через24ч, настройка UNATTACHED_UPLOAD_TTL_HOURS; активные публикации защищены. Редкие файлы без метаданных после неопределённого COMMIT не удаляются вслепую и требуют проверки storage inventory.
- Build context исключает все data, .env-варианты, ключи и каталоги инструментов; Dockerfile копирует только явно перечисленные исходники/конфигурацию сборки. Рабочие профили, uploads и ключи не попадают в образ.
