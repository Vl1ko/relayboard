# Relayboard

Панель автопостинга в Telegram, MAX, WhatsApp и VK. Одна публикация раскладывается на независимые задания доставки, поэтому ошибка одного мессенджера не блокирует остальные.

## Что уже работает

- подключения личных аккаунтов Telegram, MAX, VK и WhatsApp;
- удаление подключений вместе с относящимися к ним беседами и доставками;
- группы, каналы и беседы как адресаты;
- немедленная, отложенная и повторяющаяся отправка;
- текст и ссылка на изображение;
- пять попыток доставки с экспоненциальной задержкой;
- идемпотентность одного запуска расписания;
- журнал статусов и ручной повтор;
- AES-256-GCM для токенов;
- QR-сессия WhatsApp и MTProto-сессия Telegram в отдельных процессах.

## Быстрый запуск

```bash
cp .env.example .env
```

Замените в `.env` значения `ADMIN_API_KEY`, `APP_ENCRYPTION_KEY`, `WHATSAPP_BRIDGE_SECRET` и `TELEGRAM_BRIDGE_SECRET` на разные длинные случайные строки. Один раз получите Telegram `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org) в разделе API development tools и сохраните их как `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`, затем запустите:

```bash
docker compose up --build
```

Панель откроется на `http://localhost:3001`. Для входа используется `ADMIN_API_KEY`.

## Подключение платформ

### Telegram

1. Администратор может один раз указать `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`; тогда поля не показываются пользователям. Если значения пустые, Relayboard покажет поля для ручного ввода и локально сохранит реквизиты вместе с Telegram-сессией.
2. В Relayboard сохраните подключение Telegram и нажмите «Войти через QR».
3. На телефоне откройте Telegram → Настройки → Устройства → Подключить устройство и отсканируйте QR. Если включена 2FA, введите пароль в панели; он не сохраняется.
4. После статуса `ready` импортируйте нужные группы и каналы из списка.

Сообщения отправляются от имени вошедшего пользователя. Telegram отслеживает злоупотребления со стороны сторонних клиентов, поэтому используйте отдельный рабочий аккаунт, не рассылайте спам и держите интервалы между публикациями.

### MAX

1. Нажмите в панели «Открыть MAX Web» или перейдите на [web.max.ru](https://web.max.ru) и войдите рабочим аккаунтом.
2. Нажмите «Скопировать команду», откройте DevTools → Console в MAX Web и выполните её. Команда сама скопирует чистый токен из локальной web-сессии в буфер — вставьте его в Relayboard без дополнительного копирования вывода Console.
3. Сохраните этот токен как подключение MAX, нажмите «Загрузить группы» и добавьте нужные группы из списка. Числовой ID подставится автоматически; ручной ввод в блоке «Новая беседа» также остаётся доступен.

У MAX официальный API предназначен только для ботов. Личный аккаунт подключается через неофициальный web-протокол; токен перестанет действовать после выхода или повторного входа, протокол может измениться без предупреждения, а аккаунт может попасть под ограничения. Используйте отдельный рабочий аккаунт и умеренную частоту.

### VK

1. Нажмите «Открыть приложения VK», создайте приложение и вставьте его ID в Relayboard.
2. Перейдите по сформированной ссылке «Получить токен через VK OAuth» и разрешите доступ к сообщениям.
3. Вставьте полученный токен или всю итоговую строку адреса в Relayboard: сервис извлечёт токен, вызовет `account.getProfileInfo` и отклонит токен сообщества.
4. Укажите `peer_id` беседы. Для чатов он имеет вид `2000000001` и выше.

Метод `messages.send` вызывается пользовательским токеном, поэтому отправителем будет личный профиль.

### WhatsApp

1. Добавьте подключение WhatsApp без токена.
2. Нажмите «Проверить QR-сессию» и отсканируйте QR-код в разделе WhatsApp «Связанные устройства».
3. После подключения панель покажет доступные группы. Нажмите «Добавить» рядом с нужной; её ID имеет вид `…@g.us`.

WhatsApp-адаптер использует WhatsApp Web, а не официальный Cloud API. Это позволяет работать с существующими группами, но Meta может завершить сессию или ограничить номер. Для этой интеграции лучше использовать отдельный рабочий номер и умеренную частоту отправки.

## Разработка без Docker

Нужны PostgreSQL и Redis. После заполнения `.env`:

```bash
npm install
npm run db:migrate
npm run dev
```

WhatsApp bridge запускается отдельно командой `npm run dev:whatsapp`, Telegram bridge — `npm run dev:telegram`.

## Формат расписания

Используется cron с пятью полями. Пример `0 9 * * 1-5` означает отправку в 09:00 по будням. По умолчанию применяется `Europe/Moscow`.

## Производственная эксплуатация

- разместите сервис за HTTPS reverse proxy;
- не публикуйте порты PostgreSQL, Redis и WhatsApp bridge;
- храните `.env` вне Git и регулярно делайте резервные копии PostgreSQL и WhatsApp-сессии;
- добавьте мониторинг числа неуспешных доставок;
- перед масштабной рассылкой уточните лимиты и правила каждой платформы.
